# Cargo Cult & Résumé-Driven Development

| Field | Value |
| :--- | :--- |
| **Category** | Anti-Pattern (Engineering Culture) |
| **Fix** | Problem-First Design, [ADRs](file:///E:/Learning/engineering-notes/08-solid-design-patterns/10-architecture/12-architecture-decision-records.md), [When NOT to Use Microservices](file:///E:/Learning/engineering-notes/08-solid-design-patterns/10-architecture/06-microservices-and-when-not-to.md) |

> **TL;DR**: Adopting Kubernetes, Kafka, GraphQL, Event Sourcing, and 15 microservices for a 5-person startup with 200 daily users—simply because Google/Netflix uses them or they look good on a résumé.

## Fix
Ask: *"What concrete problem, scale bottleneck, or team pain does this technology solve **today**—and what is its operational tax?"*
