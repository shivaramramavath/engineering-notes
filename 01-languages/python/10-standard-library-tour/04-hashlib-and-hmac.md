## What & Why

Python provides cryptographic data integrity, password hashing, and signature primitives directly in the standard library through two interconnected modules:
- **`hashlib`**: Fast, FIPS-compliant cryptographic hash algorithms: SHA-2 family (SHA-224, SHA-256, SHA-384, SHA-512), SHA-3 family, BLAKE2 (BLAKE2b, BLAKE2s), and key derivation functions (PBKDF2, scrypt).
- **`hmac`**: Keyed-Hashing for Message Authentication (RFC 2104), providing tamper-proof verification that data originated from a trusted sender holding a shared secret key.

### Motivation
In modern engineering, data must frequently be verified across untrusted network boundaries:
1. **Data Integrity**: Hashes verify that large files or build artifacts downloaded over a network were not corrupted or tampered with by adversaries.
2. **Password Security**: Passwords must never be stored in plain text or simple hashes (e.g. raw SHA-256 is vulnerable to GPU rainbow table cracking). Slow, memory-hard key derivation functions like PBKDF2 and scrypt defend against brute-force attacks.
3. **API Authentication (Webhooks)**: Services like Stripe, GitHub, and AWS authenticate webhook payloads using HMAC signatures. The recipient verifies that the payload was generated by the service and wasn't altered in transit.

### Real-World Analogy
- A **cryptographic hash (`hashlib.sha256`)** is a digital fingerprint of a document. If even a single punctuation mark is changed in a 500-page contract, the resulting fingerprint looks completely different (the avalanche effect). However, anyone who possesses the document can calculate the same fingerprint.
- An **HMAC (`hmac.new`)** is an official wax seal stamped into the document using a private family signet ring. Only someone possessing the exact signet ring (secret key) can produce the seal. The recipient uses an identical signet ring to verify that the seal is authentic and the document was not opened or altered.

### When to Use vs When Not to Use
- **Use `hashlib` for:** File integrity verification, deduplication, Git-like content-addressable storage, cryptographic nonces.
- **Use `hashlib.pbkdf2_hmac` / `hashlib.scrypt` for:** Password storage, deriving encryption keys from user passwords.
- **Use `hmac` for:** API request signing (Stripe/GitHub webhooks), session cookie authentication, distributed message validation.
- **Do Not Use:**
  - Fast hashes (SHA-256, MD5) for password storage (use PBKDF2, scrypt, or third-party Argon2/bcrypt).
  - Deprecated algorithms like MD5 or SHA-1 for security signatures (broken by collision attacks).
  - Python's built-in `hash()` function for cryptography (it is non-cryptographic and salted per process).

## Core Concepts & Mental Model

```
+-------------------------------------------------------------------------+
| Unkeyed Hashing (hashlib)                                               |
| Data Payload ------------------------> [SHA-256] --------> Digest       |
| (Anyone can compute this digest)                                        |
+-------------------------------------------------------------------------+

+-------------------------------------------------------------------------+
| Keyed Hashing (HMAC: RFC 2104)                                          |
| Secret Key --+                                                          |
|              v                                                          |
| Data ----> [ Inner Hash: H(Key XOR ipad || Data) ]                      |
|                      |                                                  |
|                      v                                                  |
|            [ Outer Hash: H(Key XOR opad || Inner) ] ----> MAC Tag       |
| (Only holders of Secret Key can compute or verify this MAC tag)         |
+-------------------------------------------------------------------------+
```

### Key Properties of Cryptographic Hashes
1. **Deterministic**: The same input always produces the exact same hash digest.
2. **Pre-image Resistance (One-Way)**: Given a hash $H$, it is computationally infeasible to find an input $M$ such that $\text{hash}(M) = H$.
3. **Collision Resistance**: It is computationally infeasible to find two distinct inputs $M_1 \ne M_2$ such that $\text{hash}(M_1) = \text{hash}(M_2)$.
4. **Avalanche Effect**: Changing a single bit in the input flips approximately 50% of the bits in the output hash.

## How It Works Internally

### 1. `hashlib` Engine and OpenSSL Binding
In CPython (`Modules/_hashopenssl.c`):
- `hashlib` is dynamically linked to OpenSSL (or LibreSSL).
- Calling `hashlib.sha256()` allocates an internal OpenSSL `EVP_MD_CTX` context structure.
- The C runtime bypasses Python's Global Interpreter Lock (GIL) during `hasher.update()` calls on buffers larger than 2,048 bytes! This allows multiple threads to hash independent multi-gigabyte files in parallel with true multicore scaling.

### 2. The Vulnerability of Length Extension Attacks
Merkle-Damgård construction hashes (MD5, SHA-1, SHA-256, SHA-512) process messages in sequential blocks.
If you naively create a message signature by hashing `hash(secret_key + message)`:
An attacker who observes `message` and `hash` can append additional data to the message and calculate the valid hash of the extended message **without knowing the secret key**!
- **Why HMAC Exists**: HMAC wraps the hash function in a nested structure:
  $$\text{HMAC}(K, m) = H\Big((K \oplus \text{opad}) \mathbin{\Vert} H\big((K \oplus \text{ipad}) \mathbin{\Vert} m\big)\Big)$$
  This nested hashing mathematical structure completely eliminates length extension attacks.
- Note: Modern algorithms like **BLAKE2** and **SHA-3** are immune to length extension attacks by design.

```python
derived_key: bytes = hashlib.pbkdf2_hmac(

    p=1,                              # Parallelization parameter
    maxmem=0,                         # Memory limit (0 = 32MB default)

```

## Code Examples

### Example 1: Streaming File Hasher for Large Files
```python
import hashlib
import io

def calculate_sha256_stream(stream, chunk_size: int = 65536) -> str:
    """
    Computes SHA-256 hash of a file or stream in 64KB chunks.
    Maintains O(1) memory usage regardless of file size (multi-gigabyte safe).
    """
    hasher = hashlib.sha256()
    while chunk := stream.read(chunk_size):
        hasher.update(chunk)
    return hasher.hexdigest()

# Verification with simulated in-memory stream
def run_hasher_demo():
    payload = b"Antigravity Python Engineering Notes Data Payload"
    stream = io.BytesIO(payload)
    digest = calculate_sha256_stream(stream)
    print(f"SHA-256 Digest: {digest}")
    print(f"Digest length:  {len(digest)} characters (256 bits)")

run_hasher_demo()
# Output:
# SHA-256 Digest: 5d1d615... (64 hex characters)
# Digest length:  64 characters (256 bits)
```

### Example 3: Secure Password Hashing and Verification with `pbkdf2_hmac`
```python
import hashlib
import secrets
from typing import Tuple

def hash_password(password: str) -> Tuple[bytes, bytes]:
    """Derives a safe key using PBKDF2-HMAC-SHA256 with a unique cryptographic salt."""
    salt = secrets.token_bytes(16)  # 128-bit unique salt per user
    iterations = 600_000            # OWASP standard workload
    key = hashlib.pbkdf2_hmac(
        "sha256",
        password.encode("utf-8"),
        salt,
        iterations,
        dklen=32
    )
    return salt, key

def verify_password(password: str, salt: bytes, expected_key: bytes) -> bool:
    iterations = 600_000
    calculated_key = hashlib.pbkdf2_hmac(
        "sha256",
        password.encode("utf-8"),
        salt,
        iterations,
        dklen=32
    )
    # MUST use constant-time comparison to prevent side-channel timing attacks
    return secrets.compare_digest(calculated_key, expected_key)

def run_password_demo():
    pwd = "CorrectHorseBatteryStaple123!"
    salt, key = hash_password(pwd)
    print(f"Salt (Hex): {salt.hex()}")
    print(f"Derived Key (Hex): {key.hex()}")

    # Valid check
    assert verify_password(pwd, salt, key) is True
    # Invalid check
    assert verify_password("WrongPassword!", salt, key) is False
    print("Password verification test passed.")

run_password_demo()
# Output:
# Salt (Hex): ...
# Derived Key (Hex): ...
# Password verification test passed.
```

### Example 4: Webhook Signature Generation and Verification with `hmac`
```python
import hmac
import hashlib
import time

def sign_webhook_payload(payload_bytes: bytes, secret_key: bytes) -> str:
    """Signs an outbound webhook payload using HMAC-SHA256."""
    return hmac.new(secret_key, payload_bytes, hashlib.sha256).hexdigest()

def verify_webhook_signature(payload_bytes: bytes, secret_key: bytes, signature_to_test: str) -> bool:

    tampered_payload = b'{"event": "invoice.paid", "amount_cents": 9000}'
    assert verify_webhook_signature(tampered_payload, secret, sig) is False
    print("Webhook security verification confirmed.")

run_webhook_demo()
# Output:

# Webhook security verification confirmed.
```

## Edge Cases, Pitfalls & Anti-Patterns

### 1. Using Fast Hashes for Password Storage
Hashing passwords with raw `hashlib.sha256("password".encode())` is a critical vulnerability. Modern GPU clusters calculate over **10 billion SHA-256 hashes per second**, allowing complete reversal of dictionary and brute-force passwords in seconds.
- **Rule**: Always use slow, salt-based key derivation functions: `hashlib.pbkdf2_hmac` or `hashlib.scrypt`.

### 2. Passing Strings Directly to `update()`
`hasher.update()` accepts **only buffer-compatible bytes**, not Python strings. Calling `hasher.update("hello")` raises `TypeError: Strings must be encoded before hashing`. Always encode explicitly: `hasher.update("hello".encode("utf-8"))`.

### 3. Comparing HMAC Signatures with `==`
Comparing cryptographic signatures using standard Python `==` introduces remote side-channel **timing attacks**. An attacker monitors sub-microsecond variations in response times to deduce valid signatures byte-by-byte. Always use `hmac.compare_digest()` or `secrets.compare_digest()`.

### Common Mistakes Table

| Bad Code | Good Code | Why | Severity |
| :--- | :--- | :--- | :--- |
| `hashlib.sha256(password.encode())` | `hashlib.pbkdf2_hmac(...)` or `scrypt` | Fast algorithms are cracked trivially on GPUs via rainbow tables. | Critical |
| `if signature == expected_sig:` | `hmac.compare_digest(sig, expected)` | Standard equality short-circuits, enabling timing attacks. | Critical |
| `hasher.update("string_val")` | `hasher.update("string_val".encode())` | `update()` raises `TypeError` on strings; requires bytes. | High |
| Hand-rolling `hashlib.sha256(key + msg)` | `hmac.new(key, msg, hashlib.sha256)` | Vulnerable to Length Extension Attacks (Merkle-Damgård). | High |
| Using `hashlib.md5()` for security | Use `sha256` or `blake2b` | MD5 is completely broken; collision attacks are trivial. | High |
| Using built-in `hash()` for persistence | Use `hashlib.sha256()` | Built-in `hash()` is randomized per Python process start (SipHash). | Medium |

## Performance & Memory Characteristics

### Throughput Benchmark on 100 MB Payload
- **BLAKE2b**: $\approx 920 \text{ MB/s}$ (Optimized for 64-bit architectures; faster than MD5).
- **SHA-256**: $\approx 480 \text{ MB/s}$ (Hardware-accelerated via OpenSSL SHA-NI instructions).
- **SHA-512**: $\approx 610 \text{ MB/s}$ (Processes 64-bit words natively).
- **PBKDF2-HMAC (600k iterations)**: $\approx 120 \text{ ms per password}$ (deliberately compute-intensive).

### GIL Release During Hashing
When hashing buffers larger than 2,048 bytes, CPython's OpenSSL wrapper explicitly releases the GIL:
```c
Py_BEGIN_ALLOW_THREADS
EVP_DigestUpdate(self->ctx, cp, len);
Py_END_ALLOW_THREADS
```
This allows multithreaded Python applications (`concurrent.futures.ThreadPoolExecutor`) to achieve near-linear parallel speedup across CPU cores when hashing distinct files.

## Best Practices & Idiomatic Patterns

1. **Always Use `hmac.compare_digest`**:
   Never compare hashes or signatures with `==` when security decisions depend on the result.
2. **Stream File Hashing in 64KB Chunks**:
   Never read multi-gigabyte files into a single in-memory bytes object before passing to `hashlib`.
3. **Use BLAKE2b for High-Throughput Internal Systems**:
   If compliance standards (e.g. FIPS 140) do not mandate NIST SHA-2, BLAKE2b provides superior hashing speed with state-of-the-art security.
4. **Always Generate Cryptographic Salts with `secrets.token_bytes()`**:
   Never reuse salts across passwords. A unique salt per password guarantees that identical passwords generate distinct hashes.

## Real-World Case Study: Cryptographic API Webhook Signing and Verification Gateway

The following gateway signs outgoing webhooks with timestamped HMAC-SHA256 signatures and verifies incoming requests against replay attacks and signature tampering.

```python
import hmac
import hashlib
import time
import json
from typing import Tuple, Optional

class WebhookSecurityGateway:
    def __init__(self, signing_secret: bytes, max_timestamp_drift_sec: int = 300):
        self.secret = signing_secret
        self.max_drift = max_timestamp_drift_sec

    def generate_signed_headers(self, payload_dict: dict) -> Tuple[str, dict]:
        """
        Serializes payload and generates Stripe-style signature headers:
        Format: t=<timestamp>,v1=<hmac_signature>
        """
        payload_bytes = json.dumps(payload_dict, sort_keys=True).encode("utf-8")
        timestamp = str(int(time.time()))

        # Signed payload binds timestamp to data: prevent replay attacks
        signed_payload = f"{timestamp}.".encode("utf-8") + payload_bytes
        signature = hmac.new(self.secret, signed_payload, hashlib.sha256).hexdigest()

        headers = {
            "Content-Type": "application/json",
            "X-Signature-Timestamp": timestamp,
            "X-Signature": f"t={timestamp},v1={signature}"
        }
        return payload_bytes.decode("utf-8"), headers

    def verify_incoming_request(self, raw_body_bytes: bytes, header_signature: str) -> bool:
        """
        Validates webhook authenticity:
        1. Parses header into timestamp and signature.
        2. Rejects timestamps older than max_drift (prevents replay attacks).
        3. Verifies HMAC-SHA256 signature in constant time.
        """
        parts = {}
        for item in header_signature.split(","):
            if "=" in item:
                k, v = item.split("=", 1)
                parts[k.strip()] = v.strip()

        if "t" not in parts or "v1" not in parts:
            return False

        try:
            req_time = int(parts["t"])
        except ValueError:
            return False

        # Anti-replay check
        now = int(time.time())
        if abs(now - req_time) > self.max_drift:
            return False

        # Re-compute expected signature
        signed_payload = f"{parts['t']}.".encode("utf-8") + raw_body_bytes
        expected_sig = hmac.new(self.secret, signed_payload, hashlib.sha256).hexdigest()

        # Constant-time comparison
        return hmac.compare_digest(expected_sig, parts["v1"])

# Verification
if __name__ == "__main__":
    secret_key = b"whsec_994820491823091820498102"
    gateway = WebhookSecurityGateway(secret_key)

    data = {"event": "subscription.renewed", "customer_id": "cust_404"}
    body_str, headers = gateway.generate_signed_headers(data)
    print("Generated Webhook Headers:\n", headers)

    # 1. Valid verification
    is_valid = gateway.verify_incoming_request(body_str.encode("utf-8"), headers["X-Signature"])
    print("\nVerification status (untampered):", is_valid)
    assert is_valid is True

    # 2. Tampered body verification
    tampered_body = body_str.replace("cust_404", "cust_HACK")
    is_tampered_valid = gateway.verify_incoming_request(tampered_body.encode("utf-8"), headers["X-Signature"])
    print("Verification status (tampered body):", is_tampered_valid)
    assert is_tampered_valid is False
```

## Interview Questions & Deep-Dive Scenarios

<details>
<summary><strong>1. Junior: Why is raw SHA-256 unsuitable for storing user passwords in a database?</strong></summary>

SHA-256 is designed to be extremely fast and computationally efficient (capable of billions of computations per second on modern consumer GPUs). If an attacker steals a database of raw SHA-256 password hashes, they can use precomputed rainbow tables or brute-force billions of guesses per second to crack passwords rapidly. Password hashing requires intentionally slow, memory-hard key derivation functions like PBKDF2, scrypt, or Argon2.
</details>

<details>
<summary><strong>2. Junior: What is the difference between <code>digest()</code> and <code>hexdigest()</code> on a hashlib hash object?</strong></summary>

- `digest()` returns the raw binary hash as a `bytes` object (e.g. 32 bytes for SHA-256).
- `hexdigest()` returns the hash formatted as a string of lowercase hexadecimal digits, containing two characters per byte (e.g. 64 characters for SHA-256), which is safe for printing, JSON serialization, and URL query strings.
</details>

<details>
<summary><strong>3. Mid: What is a length extension attack, and which hash algorithms are vulnerable to it?</strong></summary>

In hash algorithms based on the Merkle-Damgård construction (MD5, SHA-1, SHA-256, SHA-512), the output of the hash represents the complete internal state of the generator. If a system calculates an unkeyed signature as `hash(secret + message)`, an attacker who knows `message` and the resulting hash can append data to `message` and calculate the valid hash of the concatenated message without ever knowing `secret`. HMAC solves this by nesting two hashing passes. Modern algorithms like BLAKE2 and SHA-3 are immune by design.
</details>

<details>
<summary><strong>4. Mid: Why does CPython release the GIL during large <code>hasher.update()</code> operations?</strong></summary>

In CPython's `_hashopenssl.c`, whenever the byte buffer passed to `hasher.update()` exceeds 2,048 bytes, the C runtime wraps the call in `Py_BEGIN_ALLOW_THREADS` and `Py_END_ALLOW_THREADS`. Because cryptographic hashing operates entirely on C memory buffers and does not inspect Python object pointers, releasing the GIL allows multiple threads to calculate hashes on separate CPU cores simultaneously with true multicore parallel scaling.
</details>

<details>
<summary><strong>5. Senior: How does <code>scrypt</code> provide greater resistance to ASIC/GPU hardware brute-forcing than <code>PBKDF2</code>?</strong></summary>

PBKDF2 is primarily compute-bound: it repeatedly iterates an HMAC function ($N$ rounds). While compute-heavy on a CPU, an adversary can mass-produce application-specific integrated circuits (ASICs) or use thousands of GPU cores that calculate HMAC in parallel with almost zero memory overhead. `scrypt` is **memory-hard**: it requires allocating and randomly accessing a large matrix of memory (controlled by parameter $N$ and $r$, typically requiring megabytes of RAM per hash). Custom hardware cannot parallelize scrypt without provisioning expensive physical high-speed memory for every single parallel core.
</details>

<details>
<summary><strong>6. Senior: How does <code>hmac.compare_digest()</code> prevent timing attacks at the C implementation level?</strong></summary>

Standard string comparison in C terminates immediately when `s1[i] != s2[i]`. `hmac.compare_digest()` is implemented in C (`Modules/_operator.c`) using bitwise operations:
```c
int result = 0;
for (i = 0; i < length; i++) {
    result |= s1[i] ^ s2[i];
}
return (result == 0);
```
It iterates across all bytes of the inputs unconditionally, accumulating differences using bitwise XOR and OR. The loop always executes for the exact same number of clock cycles regardless of where or whether differences exist.
</details>

<details>
<summary><strong>7. Staff: How would you design a distributed cryptographic file deduplication system handling millions of concurrent uploads?</strong></summary>

1. Compute chunked content-defined hashes using rolling hash boundaries (Rabin fingerprinting or FastCDC) and SHA-256 for chunk identity.
2. Store chunks in an immutable, content-addressable storage store (CAS) keyed by `sha256_hash`.
3. Guard against **Hash Collision DoS Attacks**: Combine a 256-bit hash with file byte length verification. For untrusted public inputs, use keyed BLAKE2b or HMAC to prevent malicious users from crafting identical hash collisions to corrupt other users' files.
</details>

<details>
<summary><strong>8. Staff: What are the security and architectural implications of using <code>hashlib</code> in FIPS 140 compliant environments?</strong></summary>

When CPython is compiled against a FIPS 140 validated OpenSSL provider, non-FIPS compliant algorithms (like MD5) are blocked at the OpenSSL boundary. Attempting to execute `hashlib.md5()` raises `ValueError: [digital envelope routines: EVP_DigestInit_ex] disabled for FIPS`. If MD5 is needed strictly for non-cryptographic legacy protocols (e.g. checksumming or UUID generation), callers must explicitly pass `usedforsecurity=False`:
`hashlib.md5(data, usedforsecurity=False)`.
</details>

### Exercise 1: File Content-Addressable Storage (CAS) Namer
**Requirement:** Write a function `cas_store_name(payload: bytes) -> str` that generates a Git-like content-addressable storage path: the first 2 characters of the SHA-1/SHA-256 hex digest represent a directory name, and the remaining characters represent the filename.

<details>
<summary>Show Solution</summary>

```python
import hashlib

def cas_store_name(payload: bytes) -> str:
    digest = hashlib.sha256(payload).hexdigest()
```

```python
import hmac
import hashlib
import time

def verify_api_request(secret: bytes, body: bytes, timestamp_str: str, signature: str) -> bool:
    try:
        req_time = int(timestamp_str)
    except ValueError:
        return False
```

### Exercise 4: Multi-Algorithm Stream Checksum Calculator
**Requirement:** Write a function `multi_hash(stream)` that processes an open binary stream in a single pass and returns a dictionary with MD5, SHA-1, and SHA-256 hex digests.

<details>
<summary>Show Solution</summary>

```python
import hashlib
import io

def multi_hash(stream, chunk_size: int = 65536) -> dict[str, str]:
    h_md5 = hashlib.md5()
    h_sha1 = hashlib.sha1()
    h_sha256 = hashlib.sha256()

    while chunk := stream.read(chunk_size):
        h_md5.update(chunk)
        h_sha1.update(chunk)
        h_sha256.update(chunk)

    return {
        "md5": h_md5.hexdigest(),
        "sha1": h_sha1.hexdigest(),
        "sha256": h_sha256.hexdigest()
    }

# Test
```

```python
import hmac

def verify_stored_password_hash(stored_hash_string: str, candidate_password: str) -> bool:
```
