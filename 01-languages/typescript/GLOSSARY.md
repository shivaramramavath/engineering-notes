# TypeScript Engineering Glossary & Lexicon

> Authoritative definitions of 60+ fundamental TypeScript concepts, compiler phases, type theoretical terms, and runtime mechanics.

---

### A
- **Ambient Declaration**: A declaration (`declare var`, `declare function`, `declare module`) that introduces a symbol into TypeScript's type checker without emitting runtime JavaScript code.
- **Any**: The untyped top and bottom escape hatch. Disables all compile-time type checking for a variable; assignable to and from everything (except `never`).
- **Assertion Function**: A function marked with `asserts condition` or `asserts val is T` that signals to Control Flow Analysis (CFA) that an invariant holds if the function returns without throwing.
- **AST (Abstract Syntax Tree)**: The hierarchical tree structure generated by the TypeScript Parser representing the syntactic structure of source code.
- **Awaited**: Built-in utility type that recursively unwraps Promises (`Promise<T> -> T`).

### B
- **Binder**: The third stage of the TypeScript compiler pipeline. Scans the AST to create `Symbol` objects linking declarations across scopes.
- **Bivariance**: A relationship where types are assignable in both directions. In TypeScript, method declarations are bivariant for practical JavaScript compatibility.
- **Branded Type (Nominal Type)**: A technique that attaches a unique compile-time tag (`& { readonly __brand: unique symbol }`) to a primitive type to simulate nominal typing.

### C
- **Checker**: The fourth and largest stage of the TypeScript compiler. Performs semantic analysis, type calculation, assignability checks, and diagnostics.
- **Composite Project**: A TypeScript subproject configured with `"composite": true`, enabling incremental builds and project references via `.tsbuildinfo`.
- **Conditional Type**: A type expression of the form `T extends U ? X : Y` that selects one of two branches based on type assignability.
- **Contravariance**: Parameter assignability variance where a function accepting a wider type can safely be assigned to a function expecting a narrower type.

### D
- **Declaration Merging**: The compiler behavior of merging two or more distinct declarations sharing the same identifier into a single definition (e.g., merging interfaces).
- **Discriminated Union**: A union of object types where every member possesses a common literal property (the discriminant), enabling CFA exhaustiveness checking.
- **Distributive Conditional Type**: A conditional type that automatically distributes over union members when the checked type parameter is a bare identifier.
- **Duck Typing (Structural Subtyping)**: A typing system where type compatibility is determined solely by the shape and members of a type, rather than its explicit class hierarchy.

### E
- **Emitter**: The final stage of the TypeScript compiler pipeline. Emits JavaScript (`.js`), Source Maps (`.map`), and Declaration files (`.d.ts`).
- **Excess Property Checking (EPC)**: A compile-time check applied exclusively to fresh object literals, prohibiting properties not explicitly defined on the target interface.
- **Exhaustiveness Checking**: Ensuring all possible members of a union are handled, typically using an assignment to `never` in a `default` switch block.

### H
- **Homomorphic Mapped Type**: A mapped type of the form `[P in keyof T]` that automatically preserves `readonly` and optionality (`?`) modifiers from the source type `T`.

### I
- **Index Signature**: Syntax (`[key: string]: T`) specifying that an object can contain arbitrary dynamic properties matching a specific key and value type.
- **Infer Keyword**: A keyword used inside the `extends` clause of a conditional type to introduce a type variable deduced by the compiler.
- **Isolated Modules**: A compiler mode (`isolatedModules: true`) ensuring each file can be transpiled independently by single-file tools like Vite, SWC, and Babel.

### M
- **Mapped Type**: A generic type that transforms properties of an existing type by iterating over its keys using `[P in K]`.
- **Module Resolution**: The algorithm used by the compiler to map import specifiers (`import from "foo"`) to actual files on disk (`NodeNext`, `Bundler`).

### N
- **Never**: The mathematical bottom type representing an empty set. No value can ever be assigned to `never` (except `never` itself).
- **Non-Null Assertion Operator (`!`)**: A postfix operator informing the compiler that an expression is neither `null` nor `undefined`.

### P
- **Polymorphic Component**: A React component accepting an `as` prop that dynamically alters the underlying rendered HTML element or component while maintaining strict attribute safety.
- **Project References**: A mechanism enabling a monolithic codebase to be partitioned into modular compilation units referenced via `tsconfig.json`.

### S
- **Scanner**: The first stage of the TypeScript compiler pipeline. Converts raw source text into a sequential stream of lexical tokens.
- **Strict Mode**: A compiler flag (`strict: true`) that activates a comprehensive suite of safety checks, including `noImplicitAny` and `strictNullChecks`.
- **Symbol**: A compiler internal object created by the Binder representing a named entity (variable, function, class, interface).

### T
- **Template Literal Type**: A type constructed using backticks that performs compile-time string interpolation and pattern matching.
- **Type Guard**: A runtime check that narrows a type within a conditional block via `typeof`, `instanceof`, `in`, or custom type predicates (`val is T`).
- **Type Widening**: The compiler process of generalizing a specific literal type (e.g., `"foo"`) to its broader primitive type (`string`).

### U
- **Unknown**: The type-safe top type. Any value can be assigned to `unknown`, but no operations can be performed on it without narrowing first.

### V
- **VerbatimModuleSyntax**: A TS 5.0+ flag enforcing unambiguous import/export syntax to avoid heuristic elision bugs.
- **Void**: The absence of a return value in functions.
