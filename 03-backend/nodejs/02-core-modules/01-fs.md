# `fs` — File System

Node's built-in module for reading, writing, and managing files and directories. Nearly every backend app touches it directly or indirectly (config loading, logging, uploads, templating).

```js
import fs from "node:fs";
import fs from "node:fs/promises"; // the version you'll use most often
```

## Three different APIs for the same operations

`fs` offers the same operations in three styles — this is the single most important thing to understand before using it.

```js
// 1. Synchronous — blocks the event loop until done
const data = fs.readFileSync("file.txt", "utf-8");

// 2. Callback-based — the original Node style
fs.readFile("file.txt", "utf-8", (err, data) => {
  if (err) throw err;
  console.log(data);
});

// 3. Promise-based — modern, works with async/await
const data = await fs.promises.readFile("file.txt", "utf-8");
// or, using the dedicated promises import:
import { readFile } from "node:fs/promises";
const data = await readFile("file.txt", "utf-8");
```

| Style                      | Blocks event loop? | Use for                                                                  |
| -------------------------- | ------------------ | ------------------------------------------------------------------------ |
| `*Sync`                    | Yes                | Startup/config loading, one-off scripts — never inside a request handler |
| Callback                   | No                 | Legacy code; mostly superseded by promises now                           |
| `promises` / `async-await` | No                 | Almost everything in a modern app                                        |

**Default to `fs/promises`.** Reach for `*Sync` only at startup (e.g. reading a config file before the server starts listening) — using it inside a request handler blocks every other request while the disk I/O completes.

## Reading files

```js
import { readFile } from "node:fs/promises";

const content = await readFile("data.txt", "utf-8"); // string
const buffer = await readFile("image.png"); // Buffer, if no encoding given
```

Without an encoding, `readFile` returns a raw `Buffer` (see `06-buffer.md`) — pass `"utf-8"` (or another encoding) to get a string back directly.

---

## Writing files

```js
import { writeFile, appendFile } from "node:fs/promises";

await writeFile("output.txt", "Hello, world!"); // overwrites if it exists
await appendFile("log.txt", "New line\n"); // adds to the end
```

### Writing JSON

```js
await writeFile("data.json", JSON.stringify(data, null, 2));
```

`null, 2` pretty-prints with 2-space indentation — omit for compact, minified output.

---

## Checking existence & getting file info

```js
import { access, stat } from "node:fs/promises";
import { constants } from "node:fs";

try {
  await access("file.txt", constants.F_OK);
  console.log("exists");
} catch {
  console.log("does not exist");
}
```

```js
const stats = await stat("file.txt");
stats.isFile(); // true/false
stats.isDirectory(); // true/false
stats.size; // bytes
stats.mtime; // last modified date
```

There's no `fs.exists()` anymore (it was removed for being unreliable in async code, due to a race condition between checking and using the file) — `access()` or catching the error from the operation you actually intended to do is the standard replacement.

## Directories

```js
import { mkdir, readdir, rmdir, rm } from "node:fs/promises";

await mkdir("uploads");
await mkdir("nested/deep/folder", { recursive: true }); // create parent dirs too

const files = await readdir("uploads"); // array of filenames

await rm("uploads", { recursive: true, force: true }); // delete folder + contents
```

`rmdir` only removes an empty directory; `rm` with `{ recursive: true }` is the modern way to delete a folder and everything inside it (and is also how you remove a single file: `rm("file.txt")`).

---

## Copying, moving, deleting files

```js
import { copyFile, rename, unlink } from "node:fs/promises";

await copyFile("source.txt", "backup.txt");
await rename("old-name.txt", "new-name.txt"); // also used for moving between folders
await unlink("temp.txt"); // delete a file
```

`rename` across different filesystems/drives can fail on some platforms — for cross-device moves, copy then delete the original as a fallback.

---

## Watching for changes

```js
import { watch } from "node:fs/promises";

const watcher = watch("./config");
for await (const event of watcher) {
  console.log(event.eventType, event.filename); // "change" | "rename"
}
```

Useful for config hot-reloading or build tools. Fires on both content changes and renames — check `eventType` to distinguish. For anything more than casual use, a dedicated library (e.g. `chokidar`) handles cross-platform edge cases `fs.watch` alone doesn't.

## Streaming large files

Reading a huge file entirely into memory with `readFile` can exhaust memory or block for a long time. For large files, use streams instead (full coverage in `05-streams.md`):

```js
import { createReadStream, createWriteStream } from "node:fs";

const readStream = createReadStream("large-file.zip");
const writeStream = createWriteStream("copy.zip");

readStream.pipe(writeStream);
```

This processes the file in chunks rather than loading it all at once — the standard approach for file uploads/downloads, log processing, and video/audio handling.

## Common pattern: safe config loading at startup

```js
import { readFileSync } from "node:fs";

let config;
try {
  config = JSON.parse(readFileSync("./config.json", "utf-8"));
} catch (err) {
  console.error("Failed to load config.json:", err.message);
  process.exit(1);
}
```

Synchronous and throwing on failure is the right call here — the app genuinely can't proceed without its config, so blocking briefly at startup (before anything else is happening anyway) is harmless, and failing loudly is better than starting in a broken state.

## Common mistakes

- **Using `*Sync` functions inside request handlers** — blocks the entire event loop, meaning every other in-flight request stalls until the disk operation finishes. Fine at startup, harmful in a hot path.
- **Loading huge files with `readFile` instead of streaming** — reads the entire file into memory at once; fine for a few KB/MB, risky for anything large (video, big CSVs).
- **Forgetting `{ recursive: true }`** on `mkdir` when the parent folders might not exist yet — throws `ENOENT` otherwise.
- **Assuming paths are OS-independent strings you can just concatenate** — use the `path` module (`02-path.md`) instead of manually joining with `/` or `\`.

## Quick summary

- Three APIs exist for every operation: `*Sync` (blocking), callback (legacy), and `promises` (preferred)
- `fs/promises` + `async/await` is the default choice for anything inside a running server
- `readFile`/`writeFile` for whole-file operations; streams for large files
- No `fs.exists()` — use `access()` or handle the error from the real operation instead
- `rm({ recursive: true })` is the modern way to delete folders/files; `mkdir({ recursive: true })` creates nested folders
