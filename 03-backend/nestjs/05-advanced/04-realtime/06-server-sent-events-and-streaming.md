# Server-Sent Events (SSE) and HTTP Streaming in NestJS

- **NestJS Version**: 11.x
- **Node.js Baseline**: >= 20.0.0
- **Module**: 05-advanced / 04-realtime
- **Prerequisites**: [02-fundamentals/13-serving-static-and-sse](../../02-fundamentals/13-serving-static-and-sse.md), [01-gateways-and-events](./01-gateways-and-events.md)

---

## 1. Context & Purpose

Not all real-time requirements require bidirectional WebSocket communication. Workflows such as live dashboard metrics, stock tickers, system health monitoring, AI LLM token streaming (ChatGPT-style interfaces), and background job progress are strictly **unidirectional**: the server streams continuous updates down to the client.

Setting up WebSockets for unidirectional streaming introduces unnecessary complexity: custom connection handshakes, TCP socket exhaustion, firewall traversal issues, and complex horizontal scaling with Redis adapters.

**Server-Sent Events (SSE)** uses standard HTTP persistent connections (`text/event-stream`), natively supported by browsers via `EventSource` with automated reconnections, HTTP/2 multiplexing, and simple CDN caching. NestJS provides the `@Sse()` decorator powered by RxJS `Observable` streams.

---

## 2. Theoretical Foundations

### 2.1 The SSE Protocol Specification
SSE operates over a single HTTP response:
```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive
Transfer-Encoding: chunked

event: progress
id: 101
data: {"percentage": 45}

event: progress
id: 102
data: {"percentage": 90}
```

### 2.2 Comparison: WebSockets vs SSE

| Feature | WebSockets (RFC 6455) | Server-Sent Events (SSE) |
|---|---|---|
| Direction | Full-duplex bidirectional | Unidirectional (Server -> Client) |
| Protocol | WebSocket (ws:// or wss://) | Standard HTTP (http:// or https://) |
| Format | Binary or Text frames | UTF-8 Text (`data: ...\n\n`) |
| Auto-Reconnect | Requires client library (Socket.io) | Native browser `EventSource` |
| HTTP/2 Support | Complex multiplexing | Native HTTP/2 multiplexing |
| Firewall / Proxy | Blocked by some corporate proxies | Transparently passes through standard HTTP |

## 3. Architecture & Internal Mechanics

```
Browser Client (`new EventSource('/stream')`)
                      │
                      ├─> GET /stream (Accept: text/event-stream)
                      │
                      ▼
            @Sse() Route Handler
                      │
                      ▼
         RxJS Observable<MessageEvent>
                      │
           Event Producer (e.g. LLM / Subject)
           stream$.next({ data: 'chunk' })
                      │
                      ▼
         HTTP Response Output Buffer
         data: "chunk"\n\n
                      │
                      ▼
         Client receives real-time text chunk
```

## 4. Concrete Implementation

### 4.1 LLM Token Streaming via `@Sse()`

Streaming AI tokens as they are generated by an LLM model (e.g. OpenAI / Anthropic):

```typescript
// src/ai/ai.controller.ts
import { Controller, Sse, Post, Body, MessageEvent } from '@nestjs/common';
import { Observable, Subject } from 'rxjs';
import { map } from 'rxjs/operators';
import { AiStreamingService } from './ai-streaming.service';

@Controller('ai')
export class AiController {
  constructor(private readonly aiService: AiStreamingService) {}

  @Sse('chat-stream')
  streamAiResponse(@Body('prompt') prompt: string): Observable<MessageEvent> {
    const subject$ = new Subject<string>();

    // Initiate LLM stream in background
    this.aiService.generateStream(prompt, (chunk: string) => {
      subject$.next(chunk);
    }, () => {
      subject$.complete();
    });

    return subject$.asObservable().pipe(
      map((token) => ({
        data: { token },
        type: 'token',
      })),
    );
  }
}
```

### 4.2 Multi-Client Broadcast Stream with RxJS Subject

Broadcasting live cryptocurrency prices to thousands of connected clients:

```typescript
// src/market/market.service.ts
import { Injectable, OnModuleInit } from '@nestjs/common';
import { Subject, Observable } from 'rxjs';

export interface TickerData {
  symbol: string;
  price: number;
  timestamp: string;
}

@Injectable()
export class MarketService implements OnModuleInit {
  // Multicast Subject to broadcast to multiple subscribers
  private readonly ticker$ = new Subject<TickerData>();

  onModuleInit() {
    // Simulate real-time price updates every second
    setInterval(() => {
      const price = Number((60000 + (Math.random() * 200 - 100)).toFixed(2));
      this.ticker$.next({
        symbol: 'BTC/USD',
        price,
        timestamp: new Date().toISOString(),
      });
    }, 1000);
  }

  getTickerStream(): Observable<TickerData> {
    return this.ticker$.asObservable();
  }
}
```

```typescript
// src/market/market.controller.ts
import { Controller, Sse, MessageEvent } from '@nestjs/common';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';
import { MarketService } from './market.service';

@Controller('market')
export class MarketController {
  constructor(private readonly marketService: MarketService) {}

  @Sse('btc')
  streamBtcPrice(): Observable<MessageEvent> {
    return this.marketService.getTickerStream().pipe(
      map((ticker) => ({
        data: ticker,
        id: ticker.timestamp,
        type: 'price_update',
        retry: 3000, // Reconnect after 3s if dropped
      })),
    );
  }
}
```

## 5. Edge Cases & Failure Modes

### 5.1 Nginx and Cloudflare Response Buffering
Reverse proxies buffer HTTP response bodies by default before sending them to the client. In an SSE connection, buffering delays the events until 4KB or 16KB of data accumulates, destroying the real-time stream.
- **Handling**: Instruct the proxy not to buffer the response by setting appropriate headers:
```typescript
res.setHeader('X-Accel-Buffering', 'no'); // Nginx
res.setHeader('Content-Type', 'text/event-stream');
res.setHeader('Cache-Control', 'no-cache, no-transform');
```

### 5.2 Browser Connection Limits over HTTP/1.1
In HTTP/1.1, browsers enforce a strict limit of **6 concurrent connections** per domain. Opening 6 SSE tabs completely freezes all subsequent HTTP requests (`fetch`, `script` tags) to that domain!
- **Remedy**: Always deploy SSE over **HTTP/2**. In HTTP/2, hundreds of SSE streams and HTTP requests are multiplexed over a single TCP connection.

---

## 6. Performance & Memory Implications

- **Multiplexing on HTTP/2**: 1,000 open SSE streams consume almost zero additional socket overhead when served over HTTP/2.
- **Garbage Collection**: When the browser tab closes, the HTTP connection terminates. NestJS automatically unsubscribes from the RxJS Observable, cleanly stopping internal interval timers or stream generators.

---

## 7. Anti-Patterns & Common Mistakes

- **Using WebSockets for Unidirectional Dashboards**: Deploying Socket.io gateways, Redis adapters, and ping/pong handlers just to push a metric to a browser once every 10 seconds.
- **Forgetting Reconnection IDs**: Omitting the `id` field. When an `EventSource` reconnects, it sends `Last-Event-ID`. Without IDs, the server cannot replay missed events.
- **Sending Unescaped Multi-Line Strings**: SSE data fields must be formatted line by line (`data: line1\ndata: line2\n\n`). Serializing JSON strings (`JSON.stringify()`) avoids multi-line protocol formatting errors.

---

## 8. Production Checklist & Operational Readiness

- [ ] HTTP/2 enabled on load balancers to avoid the 6-connection HTTP/1.1 browser limit.
- [ ] `X-Accel-Buffering: no` header configured for Nginx reverse proxies.
- [ ] Regular heartbeat comments (`: ping\n\n`) emitted every 15–30s to keep NAT firewalls alive.
- [ ] RxJS observables cleaned up upon client disconnect.

## 10. Verification & Testing

Unit testing an SSE controller method:

```typescript
import { MarketController } from './market.controller';
import { firstValueFrom, of } from 'rxjs';

describe('MarketController (SSE)', () => {
  let controller: MarketController;
  let mockMarketService: any;

  beforeEach(() => {
    mockMarketService = {
      getTickerStream: () => of({ symbol: 'BTC', price: 65000, timestamp: '100' }),
    };
    controller = new MarketController(mockMarketService);
  });

  it('transforms market stream into valid MessageEvent', async () => {
    const event = await firstValueFrom(controller.streamBtcPrice());

    expect(event).toBeDefined();
    expect(event.type).toBe('price_update');
    expect((event.data as any).price).toBe(65000);
  });
});
```

## 11. Comprehensive Examples

### Client-Side Browser `EventSource` Implementation

```javascript
// client/sse-client.js
const eventSource = new EventSource('/market/btc');

eventSource.addEventListener('price_update', (event) => {
  const data = JSON.parse(event.data);
  console.log(`Live ${data.symbol} Price: $${data.price}`);
  document.getElementById('btc-ticker').innerText = `$${data.price}`;
});

eventSource.onerror = (err) => {
  console.warn('SSE connection dropped. Browser will automatically reconnect...', err);
};
```
