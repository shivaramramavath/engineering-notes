# Data Splitting and Cross-Validation Strategies

## 1. Context & Problem Statement

The central objective of machine learning is generalization: achieving accurate predictions on unseen data generated by the same distribution. If we evaluate a model on the same data used to fit its parameters, empirical risk minimization guarantees an over-optimistic evaluation that severely underestimates generalization error.
Partitioning data incorrectly introduces catastrophic evaluation failures:
1. **The Independent and Identically Distributed (IID) Fallacy**: Applying random splits to grouped data (e.g., medical records with 50 scans per patient) places scans from the *same patient* in both training and testing folds. The model memorizes patient anatomy rather than disease pathology.
2. **Temporal Lookahead in Time-Series**: Shuffling time-series observations randomly allows the model to predict past events using future information, creating invalid validation metrics.
3. **Optimistic Hyperparameter Selection Bias**: Tuning hyperparameters on a single validation set causes the chosen configuration to overfit the quirks of that specific validation split.

## 3. Core Theory & Mathematical Formulation

### 3.1 K-Fold Cross-Validation

The dataset $D = \{(x_i, y_i)\}_{i=1}^N$ is partitioned into $K$ disjoint, approximately equal-sized subsets $D_1, D_2, \dots, D_K$:

$$\bigcup_{k=1}^K D_k = D, \quad D_j \cap D_k = \emptyset \quad (\forall j \neq k)$$

In iteration $k \in \{1, \dots, K\}$:
- Training set: $D_{-k} = D \setminus D_k$
- Validation set: $D_k$
- Model $\hat{f}_{-k}$ is fitted on $D_{-k}$, and evaluated on $D_k$ using loss function $\mathcal{L}$:
  $$\text{CV}_{(k)} = \frac{1}{|D_k|} \sum_{i \in D_k} \mathcal{L}(y_i, \hat{f}_{-k}(x_i))$$

The overall cross-validation estimate is the sample mean of fold errors:
$$\text{CV}_K = \frac{1}{K} \sum_{k=1}^K \text{CV}_{(k)}$$

Standard Error of the CV Estimate:
$$\text{SE}(\text{CV}_K) = \frac{s}{\sqrt{K}} = \sqrt{\frac{\sum_{k=1}^K (\text{CV}_{(k)} - \text{CV}_K)^2}{K(K - 1)}}$$

### 3.2 Nested Cross-Validation (Double Loop)

To obtain an **unbiased estimate of generalization error** while performing hyperparameter optimization, the search and evaluation must be decoupled into two nested loops:

```
+-----------------------------------------------------------------------------+
|                          OUTER LOOP: K_outer Folds                          |
|         (Estimates True Generalization Performance on Unseen Data)          |
|                                                                             |
|   +---------------------------------------------------------------------+   |
|   |                      INNER LOOP: K_inner Folds                      |   |
|   |         (Optimizes Hyperparameters theta* on Outer Train Fold)      |   |
|   +---------------------------------------------------------------------+   |
|                                     |                                       |
|                                     v                                       |
|               Train Model with Best theta* on Outer Train Fold              |
|                                     |                                       |
|                                     v                                       |
|               Evaluate on Isolated Outer Test Fold                          |
+-----------------------------------------------------------------------------+
```

1. **Outer Loop**: Partitions data into $K_{\text{outer}}$ splits. For each outer split:
   a. **Inner Loop**: Partitions the outer training set into $K_{\text{inner}}$ splits to evaluate hyperparameter grid $\Theta$.
   b. Select optimal configuration $\theta^* = \arg\min_{\theta \in \Theta} \text{CV}_{\text{inner}}(\theta)$.
   c. Train model on the entire outer training set using $\theta^*$.
   d. Evaluate this tuned model on the untouched outer test fold: $E_{\text{outer}}^{(k)}$.
2. Final generalization score is the average of the $K_{\text{outer}}$ test fold scores.

### 3.3 Walk-Forward Time-Series Split

For temporally ordered data $(x_1, t_1), (x_2, t_2), \dots, (x_N, t_N)$ where $t_1 < t_2 < \dots < t_N$:
- In fold $k$, training set is $S_{\text{train}} = \{i \mid t_i \le T_k\}$.
- Validation set is $S_{\text{val}} = \{i \mid T_k + \text{gap} < t_i \le T_k + \text{gap} + \Delta t\}$.
- The window can be **expanding** (all history included) or **rolling** (fixed window size $W$).
- The parameter `gap` prevents contamination when features use multi-day lag summaries.

## 4. Practical Implementation

Below is a self-contained, production-grade Python script demonstrating `StratifiedKFold`, `GroupKFold`, `TimeSeriesSplit`, and an end-to-end `Nested Cross-Validation` pipeline.

```python
"""
Cross-Validation Protocols & Generalization Benchmarks.
Tested on Python 3.11, NumPy 2.x, scikit-learn 1.9.x.
"""

from typing import Dict, List
import numpy as np
import pandas as pd
from sklearn.datasets import make_classification
from sklearn.model_selection import (
    KFold,
    StratifiedKFold,
    GroupKFold,
    TimeSeriesSplit,
    GridSearchCV,
    cross_val_score
)
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import roc_auc_score


def verify_cross_validation_schemes():
    np.random.seed(42)

    # -------------------------------------------------------------
    # 1. StratifiedKFold vs Standard KFold (Class Preservation)
    # -------------------------------------------------------------
    y_imbalanced = np.array([0] * 90 + [1] * 10)  # 10% minority
    X_dummy = np.random.randn(100, 2)

    skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
    minority_proportions = []
    for train_idx, val_idx in skf.split(X_dummy, y_imbalanced):
        prop = np.mean(y_imbalanced[val_idx])
        minority_proportions.append(prop)

    print("--- StratifiedKFold Minority Proportions across Folds ---")
    print([f"{p:.2f}" for p in minority_proportions])
    # Every fold must maintain exactly 10% minority
    assert np.allclose(minority_proportions, 0.10), "StratifiedKFold failed to preserve exact class ratio."

    # -------------------------------------------------------------
    # 2. GroupKFold (Leakage Prevention across Entities)
    # -------------------------------------------------------------
    # 100 samples from 10 distinct patients (10 records per patient)
    patient_ids = np.repeat(np.arange(10), 10)
    gkf = GroupKFold(n_splits=5)

    print("\n--- GroupKFold Patient Isolation Check ---")
    for fold, (train_idx, val_idx) in enumerate(gkf.split(X_dummy, y_imbalanced, groups=patient_ids)):
        train_patients = set(patient_ids[train_idx])
        val_patients = set(patient_ids[val_idx])
        overlap = train_patients.intersection(val_patients)
        print(f"Fold {fold}: Train Patients: {len(train_patients)}, Val Patients: {len(val_patients)}, Overlap: {overlap}")
        assert len(overlap) == 0, f"Patient leakage detected in fold {fold}!"

    # -------------------------------------------------------------
    # 3. TimeSeriesSplit (Walk-Forward Temporal Split)
    # -------------------------------------------------------------
    tscv = TimeSeriesSplit(n_splits=4, gap=1)
    print("\n--- TimeSeriesSplit Indices (Forward Order) ---")
    for fold, (train_idx, val_idx) in enumerate(tscv.split(X_dummy)):
        print(f"Fold {fold}: Train Max Index={max(train_idx)}, Val Min Index={min(val_idx)}")
        assert max(train_idx) < min(val_idx), "Temporal leakage: Train contains future indices relative to Val!"

    # -------------------------------------------------------------
    # 4. Nested Cross-Validation Benchmark
    # -------------------------------------------------------------
    X, y = make_classification(n_samples=200, n_features=10, random_state=42)
    
    # Inner loop: 3-fold CV for hyperparameter tuning
    inner_cv = StratifiedKFold(n_splits=3, shuffle=True, random_state=42)
    param_grid = {"n_estimators": [10, 30], "max_depth": [3, 5]}
    grid_search = GridSearchCV(
        estimator=RandomForestClassifier(random_state=42),
        param_grid=param_grid,
        cv=inner_cv,
        scoring="roc_auc"
    )

    # Outer loop: 5-fold CV to evaluate generalization of the tuned pipeline
    outer_cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
    nested_scores = cross_val_score(grid_search, X, y, cv=outer_cv, scoring="roc_auc")

    print("\n--- Nested Cross-Validation ROC-AUC Scores ---")
    print(f"Fold Scores: {nested_scores.round(4)}")
    print(f"Unbiased Generalization ROC-AUC: {nested_scores.mean():.4f} +/- {nested_scores.std():.4f}")
    assert nested_scores.mean() > 0.70

    print("\n[SUCCESS] Cross-validation invariants verified.")


if __name__ == "__main__":
    verify_cross_validation_schemes()
```

## 5. Edge Cases, Pitfalls & Failure Modes

| Failure Mode | Root Cause | Observable Symptom | Engineering Mitigation |
| :--- | :--- | :--- | :--- |
| **Random Shuffle on Grouped Data** | Records from the same patient/user scattered into both train and test | 99% validation accuracy; 55% accuracy on new patients in production | Use `GroupKFold` or `StratifiedGroupKFold` on the primary entity identifier. |
| **Temporal Lookahead** | Shuffling financial or demand records across time | Model relies on future state to predict the past; fails on day 1 of production | Strictly use `TimeSeriesSplit(gap=...)` with chronological order preserved. |
| **Non-Stratified Small Minority** | Random fold assignment leaves fold with zero positive samples | Metric raises `UndefinedMetricWarning: ZeroDivisionError` on ROC-AUC / F1 | Use `StratifiedKFold` for all classification tasks. |
| **Preprocessing Outside Cross-Validation** | Fitting scalers, imputers, or feature selectors on full dataset prior to `cross_val_score` | Artificially high validation metrics; test fold leaks into train statistics | Encapsulate all preprocessing inside an `sklearn.pipeline.Pipeline`. |
| **Small Sample High Variance** | Using $K=2$ on $N=50$ samples | Enormous variance in fold estimates ($s \gg 0.15$) | Use $K=5$ or $K=10$, or `RepeatedStratifiedKFold(n_splits=5, n_repeats=10)`. |

## 6. Production Engineering & Performance

1. **Parallel Execution via Joblib**:
   Cross-validation folds are embarrassingly parallel. Set `n_jobs=-1` in `cross_val_score` or `GridSearchCV` to saturate all CPU cores:
   $$\text{Wall-Clock Speedup} \approx \min(K, N_{\text{cores}})$$
2. **Computational Budgeting in Nested CV**:
   If the outer loop has $K_{\text{outer}} = 5$, the inner loop has $K_{\text{inner}} = 5$, and the hyperparameter grid contains $P = 20$ combinations:
   $$\text{Total Model Fits} = K_{\text{outer}} \times (1 + K_{\text{inner}} \times P) = 5 \times (1 + 100) = 505 \text{ fits}$$
   When compute is bounded, use Optuna with Bayesian optimization instead of exhaustive grid search.
3. **Deterministic Random States**:
   Always fix `random_state` in `KFold(shuffle=True)` to ensure benchmark reproducibility across team members and CI/CD pipelines.

## 7. Comparative Analysis: Splitting Strategies

| Scheme | Data Assumption | Preserves Class Proportions? | Prevents Group Leakage? | Prevents Temporal Leakage? |
| :--- | :--- | :--- | :--- | :--- |
| **K-Fold** | Independent IID, continuous $y$ | No | No | No |
| **StratifiedKFold** | Independent IID, categorical $y$ | Yes | No | No |
| **GroupKFold** | Grouped observations ($x \in \text{Group}$) | No | Yes | No |
| **StratifiedGroupKFold** | Grouped observations, categorical $y$ | Yes | Yes | No |
| **TimeSeriesSplit** | Temporally ordered observations | No | No | Yes |
| **Leave-One-Out (LOO)** | Small $N < 50$ samples | N/A | No | No |

import pytest
import numpy as np
from sklearn.model_selection import StratifiedKFold, TimeSeriesSplit

def test_stratified_kfold_proportions():
    y = np.array([0] * 80 + [1] * 20)
    X = np.zeros((100, 1))
    skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
    for _, test_idx in skf.split(X, y):
        # 16 zeros and 4 ones per fold
        assert np.sum(y[test_idx] == 1) == 4
        assert np.sum(y[test_idx] == 0) == 16

def test_timeseries_gap_invariant():
    X = np.arange(20).reshape(-1, 1)
    gap = 2
    tscv = TimeSeriesSplit(n_splits=3, gap=gap)
    for train_idx, val_idx in tscv.split(X):
        assert min(val_idx) - max(train_idx) == gap + 1

## 10. Real-World Case Study: Radiomics Cancer Detection Failure

A hospital network trained a deep learning classifier to detect malignant lung nodules from CT scans.
- **Failure**: The research team published a paper reporting 98.4% diagnostic accuracy using standard 10-Fold CV. When clinical trials deployed the model at a partner hospital, accuracy plummeted to 54.1% (barely better than a coin flip).
- **Post-Mortem Root Cause**:
  1. The training dataset had 1,200 scans from 80 patients (15 scans per patient from various angles and follow-ups).
  2. Standard random `KFold` scattered slices from the same patient across both training and validation splits.
  3. The network learned patient-specific anatomical signatures (rib cage dimensions, lung volume) rather than nodule pathology.
- **Fix**: Re-evaluated using `GroupKFold(groups=patient_id)`. Honest generalization accuracy was only 59.2%. The team re-architected the model using nodule patch crops rather than full CT scans, ultimately achieving a true 86.5% group-isolated accuracy.

## 11. Technical Interview Questions & Solutions

### Question 1: What is the trade-off in choosing $K=5$ vs $K=10$ vs Leave-One-Out (LOO) Cross-Validation?
**Answer**:
The choice of $K$ governs the **bias-variance trade-off of the validation estimator itself**:
- **Bias**: Each model is trained on a fraction $\frac{K-1}{K}$ of the total dataset. When $K=2$ (50% train), the training set is much smaller than $N$, leading to pessimistic bias (underestimating model performance). For LOO ($K=N$), each model is trained on $N-1$ samples, giving an essentially unbiased estimate of performance on the full dataset.
- **Variance**: In LOO, the $N$ training sets are virtually identical (differing by only one sample). Consequently, the $N$ fitted models are highly correlated. The variance of the mean of highly correlated random variables is high:
  $$\text{Var}\left(\frac{1}{N}\sum \hat{f}_i\right) = \frac{1}{N}\sigma^2 + \frac{N-1}{N} \text{Cov}(\hat{f}_i, \hat{f}_j)$$
  Therefore, LOO estimates often exhibit high variance.
- **Computational Cost**: LOO requires $N$ full training cycles, which is prohibitively expensive for large datasets.
*Industry Consensus*: $K=5$ or $K=10$ represents the optimal empirical sweet spot, striking low bias, moderate variance, and acceptable computational cost.

### Question 2: Why is tuning hyperparameters on the validation fold inside standard K-Fold CV optimistically biased, and how does Nested CV fix this?
**Answer**:
When we use standard $K$-Fold CV to evaluate 100 hyperparameter configurations and select the configuration that achieves the highest mean CV score:
$$\theta^* = \arg\max_{\theta} \frac{1}{K}\sum_{k=1}^K S_k(\theta)$$
The selected score $\max_\theta \text{Score}(\theta)$ is an **extreme value statistic**. Just as taking the maximum of 100 random noise variables yields a high number, the winning configuration has overfit the idiosyncratic noise of those specific $K$ folds. Reporting this winning score as the expected model performance creates optimistic selection bias.
**Nested CV** eliminates this bias by evaluating $\theta^*$ on an independent **outer test fold** that was never seen during the selection of $\theta^*$, providing a strictly unbiased estimate of real-world generalization.

### Question 3: Write a generator function that implements chronological walk-forward splits with a custom lookback window.
```python
def rolling_walk_forward_split(n_samples: int, train_window: int, test_window: int, step: int):
    """Generates rolling train and test indices preserving chronological order."""
    start = 0
    while start + train_window + test_window <= n_samples:
        train_indices = np.arange(start, start + train_window)
        test_indices = np.arange(start + train_window, start + train_window + test_window)
        yield train_indices, test_indices
        start += step
```
