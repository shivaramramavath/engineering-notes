## 1. Storage Volumes Quick Reference

### CLI Management Commands

```bash
docker volume create <volume_name>                 # Create a named volume
docker volume ls                                   # List all local volumes
docker volume inspect <volume_name>                # Inspect JSON mount point details
docker volume rm <volume_name>                     # Delete a specific volume
docker volume prune -f                             # Remove all unattached volumes
```

### Mount Syntax Comparison (`-v` vs. `--mount`)

```bash
# -------------------------------------------------------------
# 1. Named Volumes (Persistent Docker-managed storage)
# -------------------------------------------------------------
# Shorthand:
docker run -v my_data:/var/lib/data:ro my-image

# Explicit --mount syntax (Recommended):
docker run --mount type=volume,source=my_data,target=/var/lib/data,readonly my-image

# -------------------------------------------------------------
# 2. Host Bind Mounts (Local directory mapped to container)
# -------------------------------------------------------------
# Shorthand:
docker run -v $(pwd)/src:/app/src:rw my-image

# Explicit --mount syntax:
docker run --mount type=bind,source=$(pwd)/src,target=/app/src my-image

# -------------------------------------------------------------
# 3. tmpfs Mounts (In-memory volatile RAM storage)
# -------------------------------------------------------------
# Shorthand:
docker run --tmpfs /tmp:rw,noexec,nosuid,size=64m my-image

# Explicit --mount syntax:
docker run --mount type=tmpfs,target=/tmp,tmpfs-size=67108864,tmpfs-mode=1777 my-image
```

### Volume Backup & Restore One-Liners

```bash
# Backup volume data to host tarball
docker run --rm -v my_data:/data -v $(pwd):/backup alpine \
  tar -czvf /backup/my_data_backup.tar.gz -C /data .

# Restore host tarball into volume
docker run --rm -v my_data:/data -v $(pwd):/backup alpine \
  tar -xzvf /backup/my_data_backup.tar.gz -C /data
```

## 2. Container Networking Quick Reference

### CLI Network Commands

```bash
# Create custom bridge network with defined subnet
docker network create --driver bridge --subnet 10.200.0.0/24 custom-bridge

# Create encrypted overlay network (Swarm mode)
docker network create --driver overlay --opt encrypted secure-overlay

# Listing and Inspection
docker network ls                                  # List all networks
docker network inspect <net_name>                  # View connected containers and IP allocations
docker network inspect <net_name> --format '{{range .Containers}}{{.Name}} ({{.IPv4Address}}){{"\n"}}{{end}}'

# Dynamic Network Connection
docker network connect custom-bridge my-container    # Connect running container to network
docker network disconnect custom-bridge my-container # Detach container from network
docker network rm <net_name>                       # Delete network
docker network prune -f                            # Remove all unused networks
```

### Network Driver Selection Matrix

| Driver | Scope | Use Case | Key Characteristic |
|:-------|:------|:---------|:-------------------|
| **`bridge`** | Single Host | Standard multi-container apps | Default. Software bridge with private IPAM & NAT. |
| **`host`** | Single Host | High-throughput web gateways | Bypasses network namespace; uses host IP and ports. |
| **`overlay`**| Multi-Host | Docker Swarm clusters | Encapsulates packets over UDP 4789 (VXLAN). |
| **`macvlan`**| Physical LAN| Direct router IP assignment | Container receives physical MAC address on LAN. |
| **`none`** | Container | Air-gapped batch jobs | Loopback (`127.0.0.1`) only; zero network access. |

## 3. Network Troubleshooting One-Liners

```bash
# 1. Query internal container DNS from another container
docker run --rm --net custom-bridge nicolaka/netshoot nslookup target-service

# 2. Test TCP port reachability
docker run --rm --net custom-bridge nicolaka/netshoot nc -zvw3 target-service 8080

# 3. Capture live container network traffic via tcpdump
docker run --rm --net=container:<target_container_id> nicolaka/netshoot tcpdump -nn -i any

# 4. Inspect Linux iptables NAT rules generated by Docker
sudo iptables -t nat -L DOCKER -n -v

# 5. Check if port is bound on host
sudo netstat -tlpn | grep :8080
sudo ss -tulpn | grep :8080
```
