# S3: Object Storage

S3 (Simple Storage Service) stores **objects** (files plus metadata) in **buckets**, accessed over HTTPS through an API. It is effectively unlimited, extremely durable (designed for 11 nines of durability), and the default place for uploads, static assets, backups, logs, data lakes and build artifacts. Many other AWS services read from or write to S3, so you will meet it constantly.

The mental model matters more than the console: S3 is **not a file system**. It is a flat key-value store where the "key" happens to look like a path.

Prerequisites: [IAM](../01-foundations/03-iam.md) (S3 permissions are the most common IAM headache).

---

## Core concepts

```
Bucket: my-app-uploads          (globally unique name, lives in ONE region)
 ├── Key: avatars/u123.png      (the "path" is just part of the key string)
 ├── Key: avatars/u456.png
 └── Key: reports/2026/q3.pdf
```

| Concept | Details |
|---|---|
| **Bucket** | Container. Name is **globally unique across all AWS accounts**; the bucket lives in one region. |
| **Object** | Data (up to 5 TB) + metadata + key. A single `PUT` is limited to 5 GB, so larger uploads use multipart. |
| **Key** | The object's full name. `/` is just a character. The console shows folders by splitting on `/` ("prefixes"), but there are no real directories. |
| **Prefix** | Leading part of a key, used for listing and for scaling/permissions. |
| **Versioning** | Optional. Keeps every version of a key. Deleting adds a *delete marker* instead of removing data. |

Consistency: S3 offers **strong read-after-write consistency** for object writes, overwrites, deletes and listings. The old "eventual consistency" advice you'll find in older articles no longer applies.

Objects are **immutable**: you can't edit part of one. You replace the whole object (a new `PUT`). Renaming is copy + delete.

## Basic operations

```bash
aws s3 mb s3://my-app-uploads-abc123 --region ap-south-1     # make bucket
aws s3 cp ./logo.png s3://my-app-uploads-abc123/assets/logo.png
aws s3 ls s3://my-app-uploads-abc123/assets/
aws s3 sync ./dist s3://my-app-uploads-abc123/site --delete  # --delete removes extras remotely
aws s3 rm s3://my-app-uploads-abc123/assets/logo.png
```

`aws s3` is the high-level interface; `aws s3api` maps one-to-one to API calls (versioning, policies, lifecycle, etc.).

From code (TypeScript, SDK v3):

```ts
import { S3Client, PutObjectCommand, GetObjectCommand } from "@aws-sdk/client-s3";

const s3 = new S3Client({});   // region/credentials come from the environment/role

await s3.send(new PutObjectCommand({
  Bucket: "my-app-uploads-abc123",
  Key: "avatars/u123.png",
  Body: buffer,
  ContentType: "image/png",
}));

const res = await s3.send(new GetObjectCommand({ Bucket: "...", Key: "avatars/u123.png" }));
const bytes = await res.Body!.transformToByteArray();
```

Set `ContentType` on upload. Browsers use it to decide whether to render or download.

## Security: the part that matters most

Almost every S3 data leak is a configuration mistake. The defaults are now safe; keep them that way.

**Layers of access control:**

| Mechanism | Role |
|---|---|
| **Block Public Access** | Account/bucket-level master switch that overrides policies and ACLs. Leave **on**. New buckets have it on by default. |
| **IAM policies** | What your users/roles can do. The normal way to grant access. |
| **Bucket policy** | Resource-based JSON policy on the bucket. Use for cross-account access, forcing TLS, restricting to a VPC endpoint or CloudFront. |
| **ACLs** | Legacy. **Disabled by default on new buckets** (Object Ownership "bucket owner enforced"). Don't enable them. |
| **Encryption** | All new objects are encrypted at rest by default (SSE-S3). Use SSE-KMS when you need key-level control and audit; note that KMS adds request cost and its own permissions. |

A bucket policy that enforces HTTPS:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyInsecureTransport",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": ["arn:aws:s3:::my-app-uploads-abc123", "arn:aws:s3:::my-app-uploads-abc123/*"],
    "Condition": { "Bool": { "aws:SecureTransport": "false" } }
  }]
}
```

**Remember the ARN split:** bucket-level actions (`s3:ListBucket`) use the bucket ARN; object-level actions (`s3:GetObject`, `s3:PutObject`) use `bucket/*`. This trips everyone at least once.

**Same-account vs cross-account:** within one account an Allow in either the IAM policy or the bucket policy suffices; across accounts both sides must allow. If objects are encrypted with a customer-managed KMS key, the caller also needs KMS permissions.

### Sharing objects without making them public: presigned URLs

A presigned URL grants temporary access to one object, using the signer's permissions:

```ts
import { getSignedUrl } from "@aws-sdk/s3-request-presigner";
import { GetObjectCommand, PutObjectCommand } from "@aws-sdk/client-s3";

const download = await getSignedUrl(s3, new GetObjectCommand({ Bucket, Key }), { expiresIn: 300 });
const upload   = await getSignedUrl(s3, new PutObjectCommand({ Bucket, Key, ContentType: "image/png" }), { expiresIn: 300 });
```

This is the standard pattern for **direct browser uploads**: your API hands the client a presigned `PUT` URL, so file bytes never pass through your server or Lambda. The URL stops working when it expires *or* when the signing credentials do. A URL signed with short-lived role credentials can die sooner than `expiresIn` suggests.

## Storage classes and lifecycle (cost control)

Pick a class by **access pattern**; objects can move between classes automatically.

| Class | For |
|---|---|
| **Standard** | Frequently accessed data |
| **Intelligent-Tiering** | Unknown/changing access: S3 moves objects between tiers for you |
| **Standard-IA / One Zone-IA** | Infrequent access; retrieval fee and minimum storage duration apply; One Zone keeps data in a single AZ |
| **Glacier Instant / Flexible Retrieval / Deep Archive** | Archives, increasingly cheaper storage, slower/costlier retrieval |
| **Express One Zone** | Very low-latency, single-AZ storage for performance-critical workloads (uses *directory buckets*) |

Cheaper classes trade **retrieval fees, minimum duration, and latency** for lower storage price. Don't put hot data in archive classes. Check current pricing before deciding.

A **lifecycle rule** automates transitions and deletion:

```json
{
  "Rules": [{
    "ID": "tier-and-expire-logs",
    "Status": "Enabled",
    "Filter": { "Prefix": "logs/" },
    "Transitions": [{ "Days": 30, "StorageClass": "STANDARD_IA" }],
    "Expiration": { "Days": 365 },
    "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
  }]
}
```

```bash
aws s3api put-bucket-lifecycle-configuration --bucket my-app-uploads-abc123 \
  --lifecycle-configuration file://lifecycle.json
```

Always include `AbortIncompleteMultipartUpload`: abandoned multipart uploads silently accrue storage cost. With versioning on, also expire **noncurrent versions**, or old versions pile up forever.

## Useful features

- **Versioning + MFA delete / Object Lock**: protect against accidental deletion and ransomware (Object Lock gives WORM retention).
- **Event notifications**: trigger [Lambda](../02-compute/02-lambda.md), SQS, SNS or EventBridge on object creation/removal. Don't write back into the same bucket and prefix that triggers the function, or you create an infinite loop.
- **Replication** (same-region or cross-region): copy objects to another bucket, e.g. for DR or compliance. It needs versioning on both sides and only replicates new objects by default.
- **Multipart upload**: required for objects over 5 GB, recommended from roughly 100 MB up for speed and retry resilience. SDK high-level helpers (`@aws-sdk/lib-storage` `Upload`) do this for you.
- **Conditional writes**: `If-None-Match: *` on a `PutObject` fails if the key already exists, which is useful for "create only once" semantics without extra locking.
- **Static website / frontend hosting**: the modern pattern is a **private bucket behind CloudFront** with Origin Access Control, not a public bucket. See [Route 53 and CloudFront](../04-networking/02-route53-and-cloudfront.md).
- **Access Points** and **VPC endpoints (gateway endpoint for S3 is free)**: let private subnets reach S3 without a NAT Gateway, which also avoids NAT data charges. See [VPC](../04-networking/01-vpc.md).
- **Newer capabilities**: S3 Tables (managed Apache Iceberg tables) and S3 Vectors (native vector storage and similarity search) extend S3 toward analytics and AI workloads. They're specialised, so read the current docs before building on them.

## Performance notes

- S3 scales request rates **per prefix** (documented baseline of thousands of requests per second per prefix for reads and writes). Spread very hot workloads across prefixes. You no longer need random-hash key prefixes just to get throughput.
- Parallelise large transfers (multipart, byte-range `GET`s).
- Listing is paginated (1,000 keys per call) and is not a database query. If you need to search or filter by attributes, keep an index in [DynamoDB](./02-dynamodb.md) or use S3 Metadata/Inventory.
- First-byte latency is tens of milliseconds, not microseconds. For lots of tiny, hot objects consider caching (CloudFront, ElastiCache) or Express One Zone.

## Costs: what actually bills

Storage (GB-month, by class) + **requests** (PUT/LIST are pricier than GET) + **data transfer out** to the internet + features (replication, KMS requests, Inventory, Intelligent-Tiering monitoring, retrieval fees for IA/Glacier). Transfer *into* S3 and transfer to CloudFront/EC2 in the same region are generally free or cheap, but cross-region and internet egress are not. Use lifecycle rules, clean up old versions and incomplete multipart uploads, and use S3 Storage Lens/Cost Explorer to find what's growing.

## Common mistakes

- Treating S3 like a file system: expecting atomic rename, partial edits, or fast recursive listing.
- Making a bucket public to "just make it work" instead of using presigned URLs or CloudFront.
- Forgetting `bucket` vs `bucket/*` in policies.
- Bucket names: assuming they're private. They're globally unique and discoverable, so don't put secrets in names, and expect `BucketAlreadyExists` for common names.
- Missing `ContentType` → browsers download instead of render.
- CORS not configured when a browser app talks to S3 directly (presigned upload or `fetch`): symptoms are blocked requests in the browser console despite correct IAM.
- Versioning enabled with no lifecycle on noncurrent versions → ever-growing bill.
- Recursive Lambda trigger on the same bucket.
- Using `s3 sync --delete` in the wrong direction.
- Deleting a versioned bucket: you must delete all versions and delete markers first.

## Debugging `AccessDenied` and friends

| Symptom | Check |
|---|---|
| `AccessDenied` on `GetObject` | IAM policy lists `bucket/*`; bucket policy explicit Deny; **KMS key permissions** if SSE-KMS; correct identity (`aws sts get-caller-identity`) |
| `AccessDenied` on `ListBucket` | Needs `s3:ListBucket` on the **bucket** ARN (not `/*`) |
| `404 NoSuchKey` that is really a permission issue | Without `s3:ListBucket`, S3 returns 403/404 ambiguity: missing keys may appear as `AccessDenied` |
| Cross-account failure | Both the bucket policy and the caller's IAM must allow (plus KMS) |
| Presigned URL "SignatureDoesNotMatch" / expired | Region mismatch, headers differing from signed ones (e.g. `Content-Type`), clock skew, or expired credentials |
| Browser upload blocked | CORS configuration on the bucket |
| `PermanentRedirect` / wrong region errors | Client region doesn't match the bucket's region |
| Public access fails despite a "public" policy | **Block Public Access** is overriding it (that's working as intended) |

See also the general steps in [IAM](../01-foundations/03-iam.md).

## Quick Summary

- S3 = flat key-value **object** store, not a file system; objects are immutable and keys only *look* like paths.
- Buckets are regional with globally unique names; reads and listings are strongly consistent.
- Stay secure: **Block Public Access on, ACLs off, IAM/bucket policies for access, presigned URLs or CloudFront for sharing**, encryption on by default.
- Use presigned `PUT` URLs for direct browser uploads.
- Control cost with **storage classes, lifecycle rules** (including noncurrent versions and incomplete multipart uploads) and VPC gateway endpoints.
- `bucket` vs `bucket/*` in policies, CORS, and KMS permissions cause most "it should work" failures.
