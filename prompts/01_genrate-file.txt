### Quality Rules

- Be technically accurate and precise.
- Explain **what, why, how, and when**.
- Beginner-friendly without oversimplifying.
- Progress logically from basic to advanced.
- Use practical, realistic examples.
- Use correct syntax and runnable code where possible.
- Use appropriate language identifiers in code blocks.
- Use **tables** for comparisons, commands, APIs, errors, and trade-offs.
- Use **ASCII diagrams** for architecture, workflows, execution flow, or internals when useful.
- Include common misconceptions and mistakes.
- Mention version-specific behavior when relevant.
- Do not invent APIs, commands, features, versions, or links.
- Do not force irrelevant sections.
- Avoid repetition, filler, and unnecessary theory.
